React Native در بیشتر دوران حیاتش JavaScript را از طریق مؤلفه‌ای به نام bridge (پل) به کد بومی (native) متصل می‌کرد. معماری جدید (New Architecture) این وابستگی را حذف می‌کند. از نسخه‌ی 0.76، این معماری پیش‌فرض همه‌ی پروژه‌های جدید است، پس ارزش دارد بدانیم چه چیزی تغییر کرده است. همه‌ی مطالب زیر از مستندات رسمی React Native و اطلاعیه‌ی انتشار آن گرفته شده است.

## گاه‌شمار

- تیم React Native از سال ۲۰۱۸ مشغول بازطراحی ساختار درونی هسته‌ی آن بوده است [1].
- React Native **0.76** که در **۲۳ اکتبر ۲۰۲۴** معرفی شد، معماری جدید را به‌طور پیش‌فرض در همه‌ی پروژه‌ها فعال کرد [2].

## bridge چه بود و چه چیزی جایش را گرفت

در معماری قدیمی، JavaScript و کد بومی از طریق یک bridge ناهمگام (asynchronous) با هم ارتباط برقرار می‌کردند [1]. معماری جدید آن را حذف می‌کند و **JavaScript Interface (JSI)** را جایگزینش می‌کند؛ رابطی که به JavaScript اجازه می‌دهد ارجاعی به یک شیء C++ نگه دارد و برعکس [1].

یادداشت انتشار دو مزیت مستقیم حذف bridge را برمی‌شمارد: ارتباط مستقیم و کارآمد میان JavaScript و کد بومی، و راه‌اندازی سریع‌تر، چون دیگر لازم نیست bridge مقداردهی اولیه شود [2]. کد bridge برای سازگاری با نسخه‌های قبلی در دوران مهاجرت همچنان وجود دارد و تیم قصد دارد در آینده آن را به‌طور کامل حذف کند [2].

## چهار بخش معماری جدید

### Turbo Modules: سامانه‌ی جدید ماژول‌های بومی

سامانه‌ی جدید Native Module بازنویسی شیوه‌ی ارتباط JavaScript با پلتفرم است که تماماً با C++ نوشته شده است [2]. اطلاعیه این قابلیت‌ها را فهرست می‌کند [2]:

- دسترسی همگام (synchronous) به runtime بومی و از آن
- ایمنی نوع (type safety) میان JavaScript و کد بومی
- اشتراک کد میان پلتفرم‌ها
- بارگذاری تنبل (lazy loading) ماژول‌ها به‌طور پیش‌فرض

بارگذاری تنبل یعنی یک ماژول فقط زمانی در حافظه بارگذاری می‌شود که واقعاً به آن نیاز باشد، نه هنگام راه‌اندازی؛ این کار با بزرگ‌تر شدن برنامه، زمان راه‌اندازی را پایین نگه می‌دارد [2].

### Codegen: یک قرارداد نوع‌دار

با Codegen، هر ماژول یک قرارداد با نوع‌دهی قوی (strongly typed) میان لایه‌ی JavaScript و لایه‌ی بومی تعریف می‌کند [2]. تیم React Native اشاره می‌کند که خطاهای نوع در مرز میان این دو لایه یکی از رایج‌ترین منابع کرش در برنامه‌های چندسکویی (cross-platform) است [2]؛ و این همان مشکلی است که یک قرارداد تولیدشده به آن می‌پردازد.

### Fabric: رندرکننده‌ی جدید

رندرکننده‌ی (renderer) بومی نیز بازنویسی شد. به گفته‌ی یادداشت انتشار [2]:

- به‌روزرسانی‌ها می‌توانند روی رشته‌های (threads) مختلف و با اولویت‌های متفاوت رندر شوند.
- چیدمان (layout) را می‌توان به‌صورت همگام و از رشته‌های مختلف خواند.
- رندرکننده با C++ نوشته شده و میان همه‌ی پلتفرم‌ها مشترک است.

این ویژگی‌ها در کنار JSI، چیدمان همگام را ممکن می‌کنند: خواندن اندازه و موقعیت یک view بدون callback ناهمگام [1].

### یک حلقه‌ی رویداد تعریف‌شده

معماری جدید یک حلقه‌ی رویداد (event loop) کاملاً تعریف‌شده پیاده‌سازی می‌کند که از مدل پردازشی توصیف‌شده در HTML Standard پیروی می‌کند [2]. این کار به React Native توانایی می‌دهد رندر را برای رسیدگی به رویدادها قطع کند و رفتارش را به وب نزدیک‌تر می‌کند [2]. همچنین از رندر هم‌روند (concurrent rendering) و قابلیت‌هایی که در React 18 و نسخه‌های بعدی عرضه شدند پشتیبانی می‌کند [1].

## مهاجرت برنامه‌های موجود

وقتی یک برنامه ارتقا می‌یابد، روی معماری جدید اجرا می‌شود و یک لایه‌ی تعامل‌پذیری (interoperability layer) خودکار برای کتابخانه‌هایی که هنوز معماری قدیمی را هدف گرفته‌اند در اختیارش قرار می‌گیرد [2]. تیم انتظار دارد بیشتر برنامه‌ها با همان میزان تلاشِ هر انتشار دیگری به 0.76 مهاجرت کنند، و در عین حال به محدودیت‌های شناخته‌شده اشاره می‌کند: لایه‌ی تعامل‌پذیری از دسترسی به Shadow Nodeهای سفارشی یا قابلیت‌های هم‌روند پشتیبانی نمی‌کند [2].

## جمع‌بندی

- از React Native 0.76 (اکتبر ۲۰۲۴)، معماری جدید پیش‌فرض است [2].
- JSI به‌جای bridge ناهمگام، ارجاع‌های مستقیم میان JavaScript و C++ را قرار می‌دهد [1].
- Turbo Modules ماژول‌های بومیِ همگام، نوع‌دار و با بارگذاری تنبل را به ارمغان می‌آورند [2].
- Fabric روی چند رشته و با اولویت‌بندی رندر می‌کند و امکان خواندن همگام چیدمان را فراهم می‌کند [2].
